# Оптимизация рендеринга в nanotracer-rs

## Текущая архитектура

### Используемые библиотеки
- `rayon` - параллельные вычисления
- `glam` - векторная математика
- `rtbvh` - иерархия ограничивающих объемов для ускорения трассировки
- `fastrand` - генерация случайных чисел

### Структура рендера
- Изображение разбивается на тайлы (по умолчанию 16x16 пикселей)
- Каждый тайл обрабатывается параллельно с помощью `rayon`
- Внутри тайла пиксели обрабатываются последовательно
- Anti-aliasing реализован через суперсемплирование (множественные лучи на пиксель)

## Оптимизации по производительности

### 1. SIMD векторизация

#### Проблема
Текущий код обрабатывает один луч за раз, не используя векторизацию SIMD.

#### Решение
- Использовать SIMD инструкции для обработки 4-8 лучей одновременно
- Векторизовать основные математические операции (Vec3)
- Использовать библиотеку `wide` или `packed_simd` для SIMD операций

#### Пример
```rust
// Вместо обработки одного луча:
let color = cast_ray(scene, orig, dir, depth);

// Обработка 4 лучей одновременно:
let colors = cast_ray_simd(scene, origins, dirs, depths);
```

### 2. Оптимизация размера тайлов

#### Проблема
Фиксированный размер тайла 16x16 может не оптимально использовать все ядра процессора.

#### Решение
- Добавить параметр командной строки для настройки размера тайла
- Автоматически определять оптимальный размер тайла по количеству ядер
- Экспериментировать с размерами: 8x8, 32x32, 64x64

### 3. Улучшенная стратегия сэмплирования

#### Проблема
Текущий метод делает `aa_samples * aa_samples` сэмплов на пиксель, что может быть избыточно.

#### Решение
- Использовать Quasi-Monte Carlo сэмплирование вместо регулярной сетки
- Реализовать адаптивный anti-aliasing (меньше сэмплов на гладких участках)
- Использовать дешевую оценку контраста для определения сложности пикселя

### 4. Russian Roulette оптимизации

#### Проблема
Russian Roulette вычисляется для каждого луча, что может быть дорого.

#### Решение
- Упростить вычисления Russian Roulette
- Использовать предварительно вычисленные значения
- Более агрессивное прекращение трассировки для лучей с низким вкладом

### 5. Оптимизация памяти и кэш-локальности

#### Проблема
Доступ к данным может быть неэффективным из-за плохой локальности.

#### Решение
- Оптимизировать порядок обработки пикселей (по строкам или Z-кривой)
- Использовать пулы памяти для часто создаваемых объектов
- Кэшировать результаты дорогостоящих вычислений

### 6. Улучшенный BVH

#### Проблема
Текущий BVH может быть не оптимальным для всех типов сцен.

#### Решение
- Настроить параметры построения BVH (SAH, binning)
- Использовать разные стратегии для разных типов геометрии
- Попробовать alternative acceleration structures (например, LBVH)

### 7. Оптимизация материалов

#### Проблема
Обработка всех компонентов материала (diffuse, specular, reflection, refraction) происходит всегда.

#### Решение
- Добавить специализированные функции для простых материалов
- Использовать быстрые пути для материалов без отражений/преломлений
- Упростить вычисления для материалов с нулевыми альбедо

### 8. Итеративная трассировка

#### Проблема
Рекурсивная трассировка может вызвать проблемы с производительностью из-за вызовов функций.

#### Решение
- Использовать итеративный подход с явным стеком
- Уменьшить количество вызовов функций в критических путях
- Пул лучей для повторного использования

### 9. Оптимизации компиляции

#### Решение
- Использовать профиль релиза с максимальной оптимизацией:
```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
panic = "abort"
strip = true
```
- Компиляция под конкретную архитектуру: `RUSTFLAGS="-C target-cpu=native"`

### 10. Адаптивный рендеринг

#### Решение
- Использовать менее точные вычисления для удаленных объектов
- Динамическая регулировка глубины трассировки
- Уменьшение качества для быстро движущихся сцен

## Практические шаги для реализации

### Быстрые улучшения
1. Настроить размер тайла под конкретную систему
2. Использовать `cargo build --release --target-cpu=native`
3. Оптимизировать параметры глубины трассировки
4. Упростить вычисления Russian Roulette

### Среднесрочные улучшения
1. Внедрить SIMD векторизацию для основных вычислений
2. Реализовать адаптивный anti-aliasing
3. Оптимизировать структуру данных для лучшей кэш-локальности

### Долгосрочные улучшения
1. Перейти на итеративную трассировку
2. Внедрить более сложные схемы сэмплирования
3. Использовать GPU вычисления через WebGPU или CUDA
