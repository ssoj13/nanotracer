# Исследование формата 3D Gaussian Splatting (3DGS)

## Обзор формата

3D Gaussian Splatting (3DGS) - это технология представления 3D-сцен с использованием набора 3D-гауссиан, каждая из которых имеет:
- Позицию (x, y, z)
- Ковариацию (масштаб и вращение)
- Цвет (сферические гармоники для view-dependent освещения)
- Прозрачность

## Возможности записи 3DGS в текущем проекте

Проект `nanotracer-rs` уже имеет полную поддержку записи 3DGS формата:

### 1. Поддерживаемый формат
- **PLY (binary little-endian)** - стандартный формат для 3DGS
- Полная совместимость с существующими viewers (SuperSplat, bevy_gaussian_splatting и др.)

### 2. Структура данных
Каждый гауссиан в PLY файле содержит:
- Позиция: x, y, z (float32)
- Нормаль: nx, ny, nz (float32)
- SH DC: f_dc_0, f_dc_1, f_dc_2 (базовый цвет, float32)
- SH остальные: f_rest_0..f_rest_44 (45 коэффициентов до степени 3, float32)
- Прозрачность: opacity (float32, в logit-space)
- Масштаб: scale_0, scale_1, scale_2 (float32, в log-space)
- Вращение: rot_0, rot_1, rot_2, rot_3 (кватернион, float32)

### 3. Особенности реализации
- **Прямое преобразование**: Вместо традиционного подхода (изображения → 3D), используется прямой подход (3D геометрия → сплаты)
- **Полные SH коэффициенты**: Поддержка до 3-й степени сферических гармоник для view-dependent освещения
- **Параллельная обработка**: Генерация сплатов с использованием rayon для многопоточности

### 4. CLI интеграция
```bash
# Экспорт сплатов (быстрый предварительный просмотр)
nanotracer-rs -S test.ply --splat-density 50 --sh-samples 16

# Сбалансированный вариант
nanotracer-rs -S scene.ply --splat-density 200 --sh-samples 64

# Высокое качество
nanotracer-rs -S hq.ply --splat-density 500 --sh-samples 128
```

## Преимущества использования 3DGS

### 1. Производительность
- **Реал-тайм рендеринг**: Сцены, которые требуют минуты или часы для path tracing, могут быть отрендерены в реальном времени
- **GPU оптимизация**: 3DGS идеально подходит для рендеринга на GPU с использованием растеризации

### 2. Качество
- **Высокая визуальная fidelity**: Поддержка view-dependent освещения через сферические гармоники
- **Точное представление геометрии**: Прямое преобразование из исходной геометрии сохраняет детали

### 3. Компактность
- **Эффективное сжатие**: Миллионы гауссиан могут быть представлены в относительно небольших файлах
- **Оптимизация для просмотра**: Формат оптимизирован для быстрого рендеринга, а не для хранения исходных мешей

### 4. Совместимость
- **Стандартный формат PLY**: Поддержка большинством современных 3D инструментов
- **Интеграция с ML**: Подходит для использования в нейросетевых пайплайнах

### 5. Flexibility
- **Поддержка различных материалов**: Зеркала, стекло, прозрачность, отражения
- **Множественные источники света**: Правильное освещение для всех типов материалов

Проект `nanotracer-rs` уже имеет развитую систему записи 3DGS формата, которая позволяет:

# Анализ проблем, багов и возможностей улучшения сплатов

## Проблемы и баги

### 1. Несоответствие цветов между 2D рендером и сплатами
**Проблема**: Цвета в сгенерированных сплатах значительно отличаются от цветов в основном 2D рендере.

**Причина**: Несогласованная обработка цветового пространства:
- Основной рендеринг: цвета вычисляются в линейном пространстве и сохраняются без тонемаппинга
- Генерация сплатов: цвета проходят через `tonemap_srgb()` (Reinhard тонемаппинг + sRGB конверсия)

**Решение**:
- Сделать цветовую обработку консистентной в обоих пайплайнах
- Либо применить одинаковое тонемаппинг в обоих случаях, либо убрать тонемаппинг из сплат генерации

### 2. Неправильная обработка направления обзора (view direction)
**Проблема**: В комментарии к SH fitting говорится, что направление обзора должно указывать "FROM splat TO camera", но в коде используется `view_dir = -world_outgoing.normalize()`, что может быть некорректным.

**Решение**:
- Проверить и исправить конвенцию для направления обзора
- Убедиться, что направление соответствует стандарту 3DGS

### 3. Ограниченное полусферическое сэмплирование
**Проблема**: SH сэмплирование выполняется только по полусфере (вокруг нормали поверхности), но для точного представления SH обычно требуется полная сферическая выборка.

**Решение**:
- Рассмотреть полусферическое сэмплирование с обеих сторон поверхности
- Или использовать адаптивные стратегии сэмплирования в зависимости от материала

## Возможности для оптимизации

### 1. Оптимизация производительности
- **SH fitting**: Заменить общий линейный решатель на специализированный для устойчивых SH базисов
- **Параллелизм**: Улучшить распараллеливание на уровне отдельных сплатов
- **Сэмплирование**: Оптимизировать количество сэмплов на сплат в зависимости от важности

### 2. Оптимизация памяти
- **Стриминг**: Обработка сэмплов в потоковом режиме вместо хранения всех в памяти
- **Сжатие**: Использование методов сжатия для SH коэффициентов

### 3. Оптимизация качества
- **Адаптивное сэмплирование**: Изменение плотности сэмплов в зависимости от кривизны поверхности
- **Важностное сэмплирование**: Приоритизация направлений с высоким вкладом освещения
- **Улучшенные базисы**: Использование альтернативных базисов для лучшего представления
