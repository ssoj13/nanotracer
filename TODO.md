# plan_optimize.md — Ускорение трассировки (CPU + GPU варианты)

## Контекст
Текущий рендер — CPU path tracing (ray recursion) + BVH по мешам. Ускорение реально через:
1) CPU-оптимизации (быстро, минимальный риск).
2) Улучшение BVH и структуры данных.
3) GPU — это отдельный проект (переписывание рендера под compute/RT pipeline).

Ниже — поэтапный план с оценкой сложности.

---

## Этап 1: Быстрые CPU-улучшения (1–3 дня)

### 1.1 Убрать лишние аллокации и копии
- Профилировать `cast_ray_with_params` и `Scene::intersect` на предмет временных объектов.
- Проверить, где можно заменить `Vec` на pre-allocated buffers или итераторы.

### 1.2 Параллелизм
- Уже есть Rayon по пикселям. Можно:
  - Уменьшить кражу работ (chunk size) или добавить tile-based рендер (батчи 16x16, размер тайла - через опцию -ts / --tilesize с дефолтом на 16).
  - Упростить capture в замыканиях.

### 1.3 Математика и ветвления
- Cache `dir.normalize()` в местах, где направление не меняется.
- Упростить ветки в `refract/reflect` (сейчас норм ок).
- Минимизировать `powf`/`sqrt` внутри горячих циклов.

### 1.4 Тонемаппинг и sRGB
- Вызывать один раз на пиксель (уже так). Никаких доп. преобразований в ray loop.

**Ожидаемый эффект:** +10–40% скорости без изменения качества.

---

## Этап 2: BVH и пересечения (3–7 дней)

### 2.1 Заменить внутренний BVH меша на crate
- Текущий BVH самописный (см. `src/mesh.rs`).
- Варианты:
  - `rtbvh` (glam-based, SAH/LOC/Spatial) — лучший кандидат - используем
  - `bvh` требует Rust 1.87 — не подходит сейчас.

### 2.2 Scene-level BVH
- Сейчас BVH только по мешам. Для 200+ объектов нужно BVH на уровне сцены:
  - примитивы: sphere + mesh triangle AABB.
  - traversal: одна структура вместо N обходов.

### 2.3 SIMD
- `rtbvh` поддерживает более продвинутые алгоритмы и пакеты лучей.
- Можно добавить пакетную трассировку (4 или 8 лучей) при AA.

**Ожидаемый эффект:** 2x–10x на сложных сценах.

---

## Этап 3: Алгоритмические изменения (5–10 дней)

### 3.1 Ограничение рекурсии
- Ввести energy-based termination (Russian roulette) вместо фиксированного max-depth.

### 3.2 Importance sampling света
- Сэмплинг источников света важностным методом для снижения шума.

### 3.3 Материальные упрощения
- Отдельный «fast path» для diffuse-only сцен.

**Эффект:** меньше шума при равном времени, иногда +30–50% визуального качества.

## Этап 4: GPU (большой шаг)

### Варианты GPU в Rust
1) **wgpu + compute**
   - Самый реальный вариант: переписать рендер как compute shader.
   - Перенести BVH и геометрию в GPU buffers.
   - Рекурсия на GPU ограничена → нужен итеративный path tracer.

2) **Vulkan RT / RTX**
   - Использовать аппаратный ray tracing (VK_KHR_ray_tracing_pipeline).
   - Требует перехода на Vulkan (ash или erupt). Очень большой rewrite.

3) **CUDA (rust-cuda)**
   - Высокая производительность, но привязка к NVIDIA.
   - Сложная сборка/деплой, особенно Windows.

4) **OpenCL**
   - Более универсально, но менее удобно.

### Реалистичный путь
- Начать с **wgpu compute**:
  - POC: трассировать только сферы.
  - Потом добавить меши (BVH на GPU).
  - Итеративная модель (ограничение по bounce depth).

**Стоимость:** недели работы, отдельный pipeline, отдельный output.

## Предлагаемый маршрут

1) **Сделать CPU-улучшения и Scene-level BVH.**
2) **Подготовить структуру данных так, чтобы её можно было залить в GPU** (единый массив примитивов + BVH).
3) **Мини-PoC GPU** (sphere-only) на wgpu.
4) Оценить качество/сложность → решить, стоит ли продолжать GPU.
