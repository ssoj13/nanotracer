# AGENTS.md (инструкции для код-агента)

Этот репозиторий — небольшой Ray Tracer на Rust с двумя режимами работы:
1) Рендер кадра в `output.png`.
2) Экспорт сцены в **3D Gaussian Splats** (PLY) с SH-коэффициентами.

Цель этого файла: ускорить работу агента и избежать регрессий в математике/форматах.

## Быстрый старт (команды)

Требования:
- Rust **edition 2024** → нужен `rustc` **1.85+** (примерно).

Основные команды:
- Тесты: `cargo test`
- Форматирование: `cargo fmt --all`
- Рендер (быстро, без HDR): `cargo run --release`
- С процедурным небом: `cargo run --release -- -s`
- HDR окружение: `cargo run --release -- -n data/studio.exr -e 0.1`
- Экспорт сплатов в PLY: `cargo run --release -- -S scene.ply --splat-density 200 --sh-samples 64 --sh-degree 3`

Windows-скрипт:
- `.\build.ps1` делает `cargo clean`, затем `cargo build --release` и `cargo run --release`.

## Структура проекта

- `src/main.rs` — CLI (clap) + сборка сцены + выбор режима (рендер или экспорт сплатов).
- `src/renderer.rs` — рекурсивный кастинг лучей (отражение/преломление).
- `src/scene.rs`, `src/geometry.rs`, `src/material.rs` — сцена/примитивы/материалы.
- `src/environment.rs` — HDR окружение (`.exr`) и procedural sky.
- `src/splat/*` — генерация Gaussian Splats:
  - `src/splat/sampler.rs` — сэмплинг поверхности и трассировка радианса для SH-фита.
  - `src/splat/sh.rs` — SH базис + least-squares фит.
  - `src/splat/ply.rs` — запись PLY (binary little-endian).

## Главные инварианты (не ломать)

### 1) PLY-формат 3DGS
Экспорт в `src/splat/ply.rs` должен оставаться совместимым с популярными viewer’ами (SuperSplat / Luma / `bevy_gaussian_splatting`):
- `format binary_little_endian 1.0`
- Порядок и имена property важны: `x y z`, `nx ny nz`, `f_dc_0..2`, `f_rest_0..44`, `opacity`, `scale_0..2`, `rot_0..3`.
- `opacity` хранится в **logit-space**.
- `scale_*` хранится в **log-space** (`ln(sigma)`).
- `rot_*` — кватернион в порядке **wxyz**.
- `f_rest_*` — 45 float’ов (15 coeff * 3 канала) в 3DGS-раскладке: все R (coeff 1..15), затем все G, затем все B.

Если меняешь структуру `Gaussian` или раскладку SH — обновляй `done.md`/README и добавляй/расширяй тесты в `src/splat/*`.

### 2) Конвенции для SH (самое частое место регрессий)
В `src/splat/sh.rs` и `src/splat/sampler.rs` зафиксированы критичные соглашения:
- Используется **точный** real SH базис и константы как в reference 3DGS (см. комментарии в `src/splat/sh.rs`).
- `view_dir` для SH должен соответствовать viewer’у: направление **FROM camera TO splat**.
- SH коэффициенты хранятся в **feature-space** 3DGS:
  - viewer восстанавливает `color(view) ≈ 0.5 + Σ(coeff_i * Y_i(view))`.
  - поэтому при фите целевая величина — `(srgb_color - 0.5)`, а не “сырой RGB”.
- В текущем пайплайне перед SH-фитом применяется тонмаппинг и перевод в **sRGB** (см. `tonemap_srgb`), чтобы совпасть с тем, что ожидают viewer’ы.

Если сомневаешься — ориентируйся на пояснения в `done.md`.

## Соглашения по коду (Rust)

- Стиль: стандартный `rustfmt` (`cargo fmt --all`).
- Модули документируются через `//!` в начале файла (как уже сделано).
- Избегай лишних зависимостей: проект маленький; добавляй крейт только если он реально нужен.
- В hot-path (рендер/SH-сэмплинг) не добавляй аллокации и логирование внутри внутренних циклов без необходимости.
- Параллелизм: рендер и генерация сплатов используют Rayon; следи, чтобы замыкания не захватывали ненужные данные и не делали синхронизацию.

Clippy:
- Сейчас `cargo clippy --all-targets` выдаёт предупреждения (не воспринимай как “must fix” в рамках несвязанных задач).
- Если задача прямо про качество/рефакторинг — можно включить чистку clippy и затем закрепить `-D warnings`.

## Проверка изменений

Минимальный чек-лист после правок:
- `cargo test`
- `cargo fmt --all -- --check`
- (по ситуации) `cargo run --release` или `cargo run --release -- -S test.ply ...`

Если менялась математика SH / раскладка коэффициентов / PLY:
- Обязательно обнови/добавь тесты в `src/splat/sh.rs` и/или `src/splat/ply.rs`.
- Проверь экспортированный `.ply` во внешнем viewer’е (например, `bevy_gaussian_splatting` / SuperSplat).

## Файлы-артефакты и git-гигиена

- Не коммить:
  - `target/`
  - `output.png`
  - `*.ply`
  - большие бинарные ассеты, если это не оговорено явно (в `data/` уже лежит `studio.exr`).
- При поиске по коду игнорируй `target/` (иначе результаты будут шумными).

## Частые ловушки

- В `src/renderer.rs` функция `refract` при TIR сейчас возвращает “специальное” направление (`Vector3::new(1,0,0)`); в сплат-пайплайне TIR обрабатывается иначе. Если трогаешь физику преломления/отражения — согласуй поведение между пайплайнами и обнови тесты.
- Малые смещения `0.001` (self-intersection avoidance) важны; не убирай их без замены.
