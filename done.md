# Done: исправления экспорта Gaussian splats (SH/opacity/scale)

## Симптомы
- В сплат-рендере сцена выглядела «разблюренной», с «дырками».
- Стеклянные и отражающие поверхности почти не читались (пропадали/выглядели как диффузные).

## Диагноз (что было не так)
1. **Неверная конвенция `view_dir` для SH**
   - Было: конвенция направления не была согласована с тем, что ожидает `bevy_gaussian_splatting`.
   - Почему это плохо: в `bevy_gaussian_splatting` `ray_direction` для SH — это направление **FROM camera TO splat** (см. `src/render/gaussian.wgsl` в upstream). Если писать коэффициенты, ожидая противоположное направление, нечётные термы меняют знак и цвет становится «психоделическим».

2. **Неправильное кодирование SH DC/Rest под 3DGS**
   - Было:
     - `Gaussian::from_sample` пытался «перекодировать» DC как будто это RGB: `sh_dc = (rgb - 0.5)/C0`.
     - `fit_sh` делал «проекцию» через MC-интеграл по **полусфере** и выдавал коэффициенты, которые затем ещё и переинтерпретировались.
   - Почему это плохо:
     - В 3DGS коэффициенты хранятся в feature-space: `color(view) ≈ 0.5 + Σ(c_i * Y_i(view))`. То есть DC/rest — это *коэффициенты базиса*, а не «готовый цвет». Переводить DC через `(rgb-0.5)/C0` в этой схеме не нужно (и ломает масштаб).
     - Проекция через MC-интеграл по полусфере при неидеальной равномерности + без корректной постановки задачи даёт смещения и «мыло».

3. **Изотропный 3D gaussian вместо «поверхностного»**
   - Было: `scale = [ln(s), ln(s), ln(s)]` (изотропно).
   - Почему это плохо: изотропные гауссианы создают объём (foggy look) → картинка становится «мыльной», особенно на тонких объектах.

4. **Стекло становилось почти непрозрачным**
   - Было: всем сплатам ставился `opacity = logit(0.99)`.
   - Почему это плохо: в сплат-рендерерах прозрачность задаётся через `opacity` и альфа-блендинг; для стекла нужна заметно меньшая opacity, иначе оно выглядит как плотная матовая геометрия.

5. **TIR (total internal reflection) возвращал “мусорное” направление**
   - Было: при `k < 0` в `refract` возвращался `Vec3::X`.
   - Почему это плохо: это создаёт невалидные лучи и паразитные цвета при оценке отражений/преломлений.

## Что сделано (что стало)

### 1) Исправлена конвенция `view_dir`
- Файл: `src/splat/sampler.rs`
- Было: `view_dir` не соответствовал конвенции viewer’а.
- Стало: `view_dir = (-world_outgoing).normalized()` (направление FROM camera TO splat).
- Зачем: `bevy_gaussian_splatting` вычисляет `ray_direction = normalize(splat_pos - camera_pos)` и использует его в `spherical_harmonics_lookup`.

### 2) SH теперь фитятся least-squares под формулу 3DGS
- Файл: `src/splat/sh.rs`
- Было: Monte Carlo «проекция» с весом `2π/N` по полусфере.
- Стало: least-squares (нормальные уравнения `A^T A x = A^T b`) с лёгкой Tikhonov-регуляризацией.
- Плюс: радианс переводится в 3DGS feature-space через `b = clamp(color,0..1) - 0.5`.
- Зачем: стабильный фит на конечном наборе направлений и корректный масштаб коэффициентов.

### 3) DC/Rest пишутся как коэффициенты, без «перекодирования» через `C0`
- Файл: `src/splat/mod.rs`
- Было: DC пытался стать «цветом», через `(rgb-0.5)/C0`.
- Стало: `sh_dc = sh.dc()`, `sh_rest = sh.rest_interleaved()`.
- Зачем: DC/rest в PLY должны быть именно коэффициентами базиса (feature-space), а не перерасчитанным цветом.

### 4) Масштаб сделан «тонким» по нормали
- Файл: `src/splat/mod.rs`
- Было: изотропный 3D gaussian.
- Стало: `scale = [ln(tangent), ln(tangent), ln(normal)]`, где `normal ≈ 0.15 * tangent`.
- Зачем: поверхности становятся «резче» (меньше foggy/blurry).

### 5) Opacity зависит от материала (стекло менее плотное)
- Файл: `src/splat/sampler.rs`
- Было: всем `opacity_prob = 0.99`.
- Стало:
  - для материалов с рефракцией (`albedo[3] > 0`) ставится ~`0.15`
  - для остальных ~`0.98`
- Зачем: стекло начинает выглядеть прозрачным в сплат-рендере.

### 6) TIR теперь даёт отражение
- Файл: `src/splat/sampler.rs`
- Было: `Vec3::X`.
- Стало: `reflect(i, n)`.
- Зачем: корректное физическое поведение и отсутствие «битых» лучей.

### 7) Вторичные лучи при оценке reflect/refract стартуют с depth=0
- Файл: `src/splat/sampler.rs`
- Было: `cast_ray_with_params(..., depth=1, ...)`.
- Стало: `depth=0`.
- Зачем: чтобы лимиты глубины работали ожидаемо и не «съедались» на первом же вторичном луче.

### 8) Уменьшено количество «дырок» дефолтным overlap
- Файл: `src/splat/sampler.rs`
- Было: overlap `1.2`.
- Стало: overlap `1.5`.
- Зачем: более плотное покрытие поверхности при автоскейле (меньше пробелов).

### 9) Добавлен тест на корректность `fit_sh`
- Файл: `src/splat/sh.rs`
- Добавлено: `test_fit_sh_reconstructs_function` — строит синтетическую SH-функцию в feature-space, сэмплит, фитит и проверяет MSE.
- Зачем: не регрессировать математику SH и конвенцию feature-space.

### 10) SH-базис приведён к точной формуле из reference 3DGS
- Файл: `src/splat/sh.rs`
- Было: базис был реализован как «обычные» real SH, что легко расходится по знакам/полиномам с тем, что использует конкретный viewer.
- Стало: константы и полиномы совпадают с `graphdeco-inria/gaussian-splatting/utils/sh_utils.py` и `bevy_gaussian_splatting/src/material/spherical_harmonics.wgsl`.
- Зачем: устранить расхождение конвенций, которое даёт сильные цветовые артефакты.

### 11) Тонмаппинг + перевод в sRGB перед SH-фитом
- Файл: `src/splat/sampler.rs`
- Было: SH фитился по линейному radiance, хотя shader viewer’а сначала reconstruct’ит **sRGB**, а потом делает `srgb_to_linear`.
- Стало: перед SH-фитом применяется тонмаппинг (Reinhard) в линейном пространстве и затем `linear_to_srgb`, чтобы коэффициенты описывали sRGB-цвет как ожидает `bevy_gaussian_splatting`.
- Зачем: убрать систематическое искажение цвета из-за несовпадения цветового пространства.

## Побочные изменения / API
- `Gaussian::from_sample` теперь принимает дополнительный параметр `opacity_prob`.
  - Было: `from_sample(sample, sh, splat_scale)`
  - Стало: `from_sample(sample, sh, splat_scale, opacity_prob)`

- «Мылит» → уменьшай `--splat-scale`.
